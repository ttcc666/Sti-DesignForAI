# STI 智能标签设计工作台

## 业务可行性说明

| 项 | 内容 |
| --- | --- |
| 产品形态 | Windows 桌面客户端（不是网站） |
| 核心引擎 | Stimulsoft 标签 / 报表设计器（`.mrt`） |
| 智能能力 | 大模型辅助生成、改稿、分析模板（可关、可离线设计） |
| 文档用途 | 说明「可以做什么」和「做成什么样子」，供业务拍板 |
| 日期 | 2026-08-31 |
| 关联 | [产品文档](./产品文档.md)、[助手相对手工维护的好处](./助手相对手工维护的好处.md) |

---

## 1. 结论（先看这一节即可）

**这件事业务上可行，建议做成「本机标签工作台 + 可选 AI 助手」，不要做成网站，也不要做成自动出稿、无人复核的黑盒。**

- **给谁用：** 做标签模板的人（主用户）；后期可给现场人员按模板套数据打印。
- **解决什么：** 出稿慢、改规格重复、字段绑错、设计和打印两套环境对不齐。
- **做成什么样：** 装在 Windows 上的一个窗口。中间是熟悉的 STI 设计器，左边用白话提需求，右边选字段和打印机。人始终能改、能撤、能自己拖。
- **AI 的位置：** 加速「从需求到草稿」「从旧稿到改稿」，不是替代设计器和打印机。没网、没模型，照样能设计、预览、打印。
- **建议节奏：** 先做出「能打开、能改、能打」的本机工作台，再接通对话生成。第一期不要上多人协作平台、审批流、自动发布到产线。

**拍板建议：做。第一期目标是「一个人在工位上，用白话或拖拽，稳定打出一张对的标签」。**

---

## 2. 要解决的业务问题

标签不是海报，是生产工件：要扫得过、字段对得上、纸张裁得准。当前常见情况是：

1. **出一张新标签成本高。** 业务说「70×40，物料编码、品名、批次、二维码」，模板人员要在 STI 里从纸张、字号、条码、绑定一项项做。
2. **改旧模板重复劳动多。** 换打印机、改尺寸、加一个字段、换仓别/语种，往往是复制一份再手改，容易漏绑、错位。
3. **设计和打印容易对不齐。** 设计环境看不到现场打印机、纸张和字体，样张到车间才发现条码扫不上或裁切偏。
4. **能力集中在少数人。** 会 STI 的人少，业务自己说不清版式，来回沟通轮次多。

本产品不消灭 STI，而是把「设计器 + 本机打印 + 字段约束 + 对话助手」收成一个工位工具。

## 3. 给谁用、用在哪

| 角色 | 他们要完成的事 | 产品怎么帮 |
| --- | --- | --- |
| 模板设计人员（主用户） | 出新标签、改旧 `.mrt`、对样张 | 设计器仍在；白话生成草稿；字段不能绑错 |
| 业务 / 仓管 / 计划 | 说清楚要一张什么样的标签 | 用口语描述，不用会 STI |
| 现场打印人员（二期） | 选模板、套数据、打出来 | 同一套模板，本机选打印机直接打 |
| 信息化 / 管理员 | 发程序、管模型账号、管模板目录 | 安装包 + 本机/共享盘目录；模型可关 |

**使用场所：** 办公室出稿工位、车间/仓库打印工位。第一期按「单机或共享盘」部署，不按互联网 SaaS 部署。

## 4. 可以做什么

按「现在就承诺 / 第一期做完 / 以后再说」分开，避免把愿景当成交付。

### 4.1 现在就可以承诺的能力

| 能力 | 用户感知 | 业务价值 |
| --- | --- | --- |
| 本机打开、编辑、保存 `.mrt` | 和现有 STI 资产兼容，旧模板能继续用 | 不推倒重来 |
| 嵌在窗口里的设计器 | 中间画布可拖文本、条码、二维码、图、线、框 | 专业排版不另学一套软件 |
| 本机预览 | 用示例数据看成品，而不是只看占位框 | 出稿前能发现明显错误 |
| 本机打印 | 选这台电脑上的打印机、纸张，直接打样 | 设计和现场同一套驱动 |
| 页规格预设 | 一键 70×40、100×60 等常用标签尺寸 | 少调纸张 |
| 字段字典 | 品名、SKU、批次等从清单里选，不能瞎填列名 | 少打出空白或错字段 |
| 离线设计 | 没网也能打开、改、存、打 | 车间网络不稳也能用 |

### 4.2 接上大模型之后可以做的（第一期后半）

| 能力 | 用户怎么说 | 系统实际做什么 |
| --- | --- | --- |
| 白话出草稿 | 「做一张 70×40 物料标签，要编码、品名、批次、QR」 | 生成结构化草稿，铺到设计器里，人再微调 |
| 改已有模板 | 「把这张改成 100×60，批次号加大，左边加仓库」 | 先说明会改哪里，确认后改，另存一版 |
| 分析旧稿 | 「这张标签有哪些字段、有什么风险」 | 列出页尺寸、组件、绑定、可能扫不上的条码 |
| 增量改一处 | 「再加一个生产日期」「标题改成英文」 | 只改一处，不推倒重做 |
| 按字典绑定 | 「品名绑物料名称，不要写死」 | 只能绑已有字段，绑不上就说清 |
| 对照打印机 | 「用这台 TSC 打」 | 按本机打印机能力收纸张和边距 |

**用户体验上的「实时」：** 说完一句话，几秒内画布上出现或改好一块内容；继续说，继续改。不是看一段文字慢慢刷出整张 XML。

### 4.3 以后可以做、第一期不承诺

- 一次生成 10 个仓别 / 语种 / 尺寸变体
- 从 ERP/WMS 拉实时数据套打（第一期用 Excel/JSON 示例数据）
- 多人同时改同一张模板、在线审批、正式发布到产线
- 自动检查「条码能否扫过」（需要真机或专用检测，不能只靠模型看图）
- 手机端、网页端协同设计

## 5. 做成什么样子

### 5.1 产品形态

- **一个 Windows 桌面程序**，安装后开始菜单能打开。
- **一个主窗口**，不要一堆浏览器标签页。
- **模板是文件**：本地文件夹或共享盘上的 `.mrt`，和现在归档方式接近。
- **AI 是开关**：设置里填模型地址；关掉或断网，工作台还在。
- **看起来像工位工具，不像聊天网站。** 画布最大，对话是助手栏，不是主界面。

### 5.2 主界面（用户每天看见的）

```
┌──────────────────────────────────────────────────────────────┐
│  文件   打印机   模型设置   版本                              │
├────────────┬─────────────────────────────┬───────────────────┤
│            │                             │  字段             │
│  对话      │     STI 设计器（最大）        │  品名  SKU  批次  │
│            │                             │                   │
│  「做一张  │     标签画布                 │  打印机           │
│   物料标   │     可拖、可改、可撤销        │  TSC / 尺寸      │
│   签…」    │                             │                   │
│            │                             │  预览 / 打样      │
├────────────┴─────────────────────────────┴───────────────────┤
│  当前文件 · 70×40 mm · 打印机就绪 · 模型在线/离线 · 未保存     │
└──────────────────────────────────────────────────────────────┘
```

三块的职责要让用户一眼懂：

| 区域 | 做成什么样 | 用户心理 |
| --- | --- | --- |
| 中间设计器 | 熟悉的 STI 画布，占窗口一半以上 | 「我还是在做标签，不是在跟机器人聊天」 |
| 左边对话 | 短输入、短回复、带「应用到画布 / 撤销」 | 「我说人话，它动手，我能反悔」 |
| 右边栏 | 字段清单、页规格、本机打印机、示例数据 | 「数据从哪来、打到哪台，都在眼前」 |
| 顶栏 / 底栏 | 文件、版本、保存、模型是否可用 | 「现在改的是哪张、会不会丢」 |

### 5.3 关键业务长什么样（三条主路径）

**路径 A：从零出一张新标签**

1. 选规格（例如 70×40）和本机打印机。
2. 左边说需求，或右边勾字段后点「按字段生成草稿」。
3. 中间出现可编辑草稿（不是一张不可改的图片）。
4. 人改字号、对齐、位置。
5. 用示例数据预览，本机打一张样张。
6. 另存为 `.mrt`，留下一版。

**路径 B：改一张旧模板**

1. 打开现有 `.mrt`，中间就是原样。
2. 问「这张有哪些字段、有什么风险」，先看明白再改。
3. 说「改成 100×60，批次加大」。
4. 系统列出将要改的点，用户点确认。
5. 画布更新；不对就撤销，回到上一版。

**路径 C：只设计、不用 AI**

1. 和现在用 STI 一样：打开、拖拽、保存、打印。
2. 对话栏显示「模型未配置 / 离线」，不挡主操作。

### 5.4 对话应该像什么，不像什么

**像：** 短、可执行、可撤销。

- 用户：「加一个生产日期，绑字段 ProductionDate。」
- 助手：「已在右下增加文本，并绑定 ProductionDate。要不要预览？」
- 用户看见画布多了一块，可以拖走或撤销。

**不像：**

- 长篇解释 STI 原理。
- 一次生成不可编辑的效果图。
- 没问就改完整张版式。
- 字段名是模型自己编的（必须来自右边字典）。

### 5.5 成品标准（什么样叫「能用」）

一张标签「做成了」，不是「看起来像标签」，而是同时满足：

1. 本机预览和本机打印一致（字体、尺寸、边距）。
2. 字段来自字典，示例数据能套上，不出现空白绑定。
3. 条码/二维码按约定制式（如 Code128、QR），位置不贴边。
4. 旧 `.mrt` 打开不丢主内容；保存后还能再打开。
5. 人可以完全抛开 AI，把同一张稿改完打完。

## 6. 明确不做成什么样

| 不做 | 原因 |
| --- | --- |
| 网站 / 浏览器里设计 | 现场打印、本机字体、STI 桌面设计器都对不齐 |
| 自动出稿无人看就下发产线 | 标签出错是实物损失，必须人确认 |
| 用 AI 当唯一画布（抛弃 STI） | 排版、条码、旧模板资产都在 STI 上 |
| 聊天窗口刷出一整份模板源文件 | 易损坏、难撤销、用户看不懂 |
| 第一期就上审批流、多租户、手机端 | 会拖死「工位上能打一张」这个目标 |
| 承诺「模型保证扫码通过」 | 扫码取决于打印机、碳带、尺寸、静区，要真机闭环 |

## 7. 可行性判断

### 7.1 业务上：值得做

- 需求具体：出稿、改稿、打样，不是泛泛的「AI 设计」。
- 用户少而专业，不需要先做大规模运营和注册体系。
- 旧资产（`.mrt`）能接住，迁移成本低。
- AI 是加速器，关掉也不废掉主流程，业务风险可控。

### 7.2 技术上：做得到，但有边界

- **做得到：** 桌面嵌 STI 设计器、本机打印、字段约束、对话生成「结构化草稿」再铺到画布。
- **有边界：** 模型不能直接写模板源文件；复杂旧稿里的特殊脚本可能只能「看得到、不敢自动改」。
- **第一周就要验：** 设计器能否稳嵌在窗口中间；嵌不稳就改成「主窗口 + 设计器弹窗」，不影响业务目标。
- **许可要先问清：** Stimulsoft 桌面设计器/查看器是商业许可，立项时确认，避免做成了不能发。

### 7.3 成本上：主要是许可、开发和模型，不是服务器

| 成本项 | 怎么理解 |
| --- | --- |
| Stimulsoft 许可 | 固定成本，和现在用 STI 是一类支出 |
| 开发 | 工作台壳、字段/打印、草稿规则、再接对话 |
| 模型调用 | 按对话次数；可改本机模型；可完全不用 |
| 服务器 | 第一期可以没有；共享盘即可协同文件 |
| 现场 | 要留真机打样时间，否则「能用」验不了 |

第一期不需要养一套在线平台，整体比「AI 设计 SaaS」轻。

### 7.4 风险与对策（业务能听懂的）

| 风险 | 会怎样 | 怎么控 |
| --- | --- | --- |
| 把 AI 当自动排版 | 稿子花、扫不上、字段错 | 人确认；字段必须选自字典 |
| 新旧模板往返丢失 | 旧稿打开少了东西 | 先保 STI 原文件；自动改只动说得清的部分 |
| 设计和车间打印不一致 | 办公室好看、车间废标 | 本机对着现场打印机打样 |
| 模型账号/密钥在电脑上 | 泄露或被共用 | 放用户设置，可后接公司统一入口 |
| 许可未买就推广 | 现场不能用设计器 | 立项先确认许可 |

## 8. 分期：每一期「做成什么样」

| 阶段 | 业务上能看见什么 | 怎样算过关 |
| --- | --- | --- |
| 第一期前半 · 工作台 | 装上就能打开旧稿、拖拽、预览、本机打样 | 用现有一张 `.mrt` 在目标打印机打出合格样张 |
| 第一期后半 · 草稿助手 | 说一句或勾字段，中间出现可改草稿 | 「物料标签」从零到打样，明显快于纯手搭 |
| 第二期 · 改旧稿 | 打开旧模板，能分析、能按一句需求改一处并撤销 | 改尺寸/加字段不丢原绑定 |
| 第三期 · 现场化 | 变体（仓别/语种）、共享模板目录、可选接业务数据 | 现场人员能选模板套数据打印 |

**第一期成功标准（建议写进立项）：**

1. 模板人员愿意用这个窗口替代「单独开 STI + 记事本对字段」。
2. 从需求到第一张可打样张，常用物料标签能压到一次会话 + 少量微调。
3. 同一张稿，关掉 AI 也能改完、存完、打完。
4. 至少 2～3 种常用标签尺寸在目标打印机上打出可扫样张。

## 9. 需要业务拍板的事项

请业务确认下面几条，确认后就可以按第一期开工。未确认的，文档里按括号默认值推进。

1. **是不是 Windows 工位客户端？**（默认：是）
2. **现有标签是不是 Stimulsoft 的 `.mrt`？**（默认：是）
3. **第一期主用户是不是模板设计人员？**（默认：是；现场打印放后面）
4. **先做哪 2～3 种标签规格、哪几台打印机？**（需提供清单）
5. **字段以哪套为准？** 例如物料编码、品名、规格、批次、数量、日期、仓库（需一份字段表）
6. **模型能不能出外网？** 能则用公司已有模型；不能则本机/内网模型，或第一期先不做对话
7. **旧模板大概多少张、有多复杂？** 决定「自动改旧稿」能承诺到哪一步
8. **Stimulsoft 许可是否已覆盖桌面设计器发给内部用户？**（需确认）

## 10. 一句话给决策人

> 做成装在 Windows 上的标签工位：中间还是 STI，左边能用白话出草稿和改稿，右边管字段和打印机。AI 可关，打印在本机。先保证打得出、绑得对，再谈自动和协同。

如需把本文同步给评审会，建议连同「第一期成功标准」和「第 9 节待拍板清单」一起评审，不要只评审效果图。
