

## 助手相对手工维护的好处

---

## 1. 结论（先看这一节即可）

人仍是最终编辑者。助手不替代设计器和打样确认，只把重复、易错、要靠个人记规则的步骤收成白话指令。

默认路径变成四件事，而不是靠经验和记事本对字段：

1. **从需求到可改草稿**
2. **改一处不推倒整张**
3. **字段别绑错**
4. **打样前先体检**

关掉 AI，设计、预览、打印仍然完整可用。助手是加速器，不是前提条件。

**给评审一句话：**

> 助手把骨架、绑定和规则检查做成默认路径；人把时间花在对样张和难排的版式。不能无人复核就下发产线，也不能承诺扫码一定通过。

---

## 2. 八项直接好处

按产品原则排序：打得出、绑得对，高于生成得好看。下列每项对应第一期已落地能力（产品文档 F4、F7、F10 与附录 A），不是愿景。

| # | 好处 | 手工时怎样 | 用助手之后 |
| --- | --- | --- | --- |
| 1 | 从零出草稿更快 | 在 STI 里逐项设纸张、字号、条码、绑定 | 说「70×40，编码、品名、批次、QR」，或右栏勾选后生成。中间出现可拖可改的对象，不是效果图。人只做微调 |
| 2 | 字段绑错明显下降 | 复制旧稿漏绑、列名写错、记事本对错一行；预览空白，现场才发现 | 组件只能绑字典里的字段，或写死字面量。口述新字段必须先登记再使用；字典没有的名字拒绝并列出可用项 |
| 3 | 改一处，不推倒整张 | 另存一份再手改，容易漏绑定、错位 | 「加一个生产日期」「批次字号加大」只动说清的部分。换纸、重排先列清单再确认。改前先查组件 id，不为改字号重建整张 |
| 4 | 不会 STI 也能说清需求 | 业务用文字/截图来回说明版式，轮次多；能力集中在少数会 STI 的人 | 业务口语描述即可看到草稿；模板人员在设计器里收尾。沟通从「讲解版式」变成「看草稿再改一句」 |
| 5 | 打样前先体检，少出废样 | 靠经验，或打完才发现 EAN-13 少一位、图片路径丢了、组件压到边距 | 保存、打样前主动体检：条码位数/字符集/GS1 括号写法、空绑定、缺图、超页贴边、明显重叠。只报问题，不自动改 |
| 6 | 规则写进工具，不靠个人记忆 | 换人维护时要重新记住「这张该用 Code128 还是 GS1-128」 | 页规格预设、条码 39 种制式、GS1 用 AI 括号写法、文字溢出（换行/缩字/裁切）、物料/出货/货架排版，都落在同一套工具上 |
| 7 | 整笔撤销 + 另存一版 | Ctrl+Z 一步步撤；复制错文件就覆盖正式稿；文件夹乱命名 | 每条产生画布变更的回复可「撤销本次」（本轮全部改动）。大改建议另存一版，副本不覆盖正在编辑的文件。打开旧稿时，模板里多出来的字段自动登记进字典 |
| 8 | 设计、预览、打样在同一台机器 | 办公室设计、车间才对纸，条码扫不上或裁切偏 | 本机打印机队列、本机字体、示例数据预览、PDF/PNG 导出。可以说「用这台打印机」「导出 PDF」 |

## 3. 相对手工，省的是哪类时间

示意划分，不是工时统计。来源：产品文档第 2、8、12 节对纯手搭对照任务的期望。第一期不做埋点，上线后用 1～2 个对照任务实测。

| 工作环节 | 纯手工主要耗在 | 助手接手后 | 人还要做 |
| --- | --- | --- | --- |
| 从需求到第一稿 | 逐项设纸张、组件、绑定 | 一句话或勾选字段出草稿 | 看位置、改字号、对齐 |
| 字段与绑定 | 记事本对列名，复制易漏 | 只能绑字典；没有就拒绝 | 确认业务字段是否齐全 |
| 改旧稿 | 另存再手改，容易推倒 | 按 id 增量改；大改先确认 | 确认清单、微调版式 |
| 打样前检查 | 靠经验或打废了才发现 | 条码 / 空绑定 / 缺图 / 超页 | 真机扫码、看碳带与静区 |
| 留档与回退 | 覆盖保存或文件夹乱命名 | 另存一版、对话里打开某版 | 决定哪版是正式稿 |

产品期望（上线后用对照任务验证，不是当前承诺的工时）：

- 常用物料标签：从需求到第一张可打样张，明显短于纯手搭；目标是一次会话 + 少量微调即可打样。
- 打样后因「字段绑错 / 空白」返工，低于纯手搭对照任务。

## 4. 同一件事：手工怎么做，助手怎么做

左栏是当前常见做法（单独开 STI + 记事本对字段）。右栏是本工位助手的实际行为。

| 维护事项 | 人手工 | 用助手 | 差在哪 |
| --- | --- | --- | --- |
| 新开一张物料标签 | 选纸 → 拖文本/条码 → 逐个绑字段 → 调字号对齐 | 说规格和字段，或勾选后生成；画布出现可编辑草稿 | 重复搭骨架的时间压掉 |
| 加一个字段 | 拖一个文本框，手填绑定，再对位置 | 「加一个生产日期」：先登记（如需要）再插入并绑定 | 少漏绑、少写错列名 |
| 换页尺寸 | 改纸张后组件可能超页，再一个个挪 | 大改先列出将要做的事；可把内容收回页内 | 避免无意裁切，改前有确认 |
| 看旧稿有什么 | 点开每个组件看属性，或靠记忆 | 「这张有哪些字段、有什么风险」列出页尺寸、绑定、风险 | 改之前先看明白，少误删 |
| 条码换制式 | 在属性里找制式，GS1 内容格式靠人记 | 「换成 GS1-128」；内容走 `(01)…(17)…(10)…`；可先列出本机制式 | 制式和写法有工具约束 |
| 品名装不下 | 试字号、试换行，凭感觉 | 溢出处理：换行 / 自动缩字 / 裁切；长中文默认可缩字 | 少出现打印裁切半个字 |
| 对齐与等距 | 靠网格和眼睛 | 「这三块左对齐」「间距均匀」「等宽高」「复制一份」 | 机械排版一次对齐 |
| 绑定不存在的列 | 保存后预览空白，现场才发现 | 拒绝改画布，列出可用字段 | 错误发生在说话这一秒，不是打样之后 |
| 打开旧 `.mrt` | 模板里的字段若字典没有，绑定悬空 | 自动登记并勾选，避免旧稿绑定悬空 | 兼容旧资产，少一次手工补字典 |
| 打样 / 导出给业务 | 菜单里找预览、打印、另存图片 | 可以说「体检一下」「打样」「导出 PDF」 | 出稿闭环不用离开对话 |
| 改坏了 | Ctrl+Z 若干步，或从备份文件夹找回 | 撤销本轮全部改动；或打开历史版本 | 回退粒度是「这一句话」，不是像素级一步 |
| 没网 / 关模型 | 本来就能用手做（如果只开 STI） | 设计器、字段、预览、打印仍可用；仅对话禁用 | 助手是加速器，不是前提条件 |

和「另做一套 AI 画布」的区别：助手只通过工具改模板，不向用户输出 `.mrt` 或 XML。中间仍是 Stimulsoft，旧稿能打开、能保存、能再打开。好处来自约束和闭环，不是换掉设计器。

## 5. 三条主路径上的差别

对应产品文档 8.1–8.3。助手的价值不平均：从零出常用标签最大；复杂旧稿次之；纯手搭路径仍然完整保留。

### 5.1 路径 A：从零出一张新标签

| | 步骤 |
| --- | --- |
| 手工 | 选规格 → 拖组件 → 绑字段 → 调版式 → 找示例数据 → 预览 → 打样。每张都从骨架做起 |
| 助手 | 选规格后说一句话或勾字段 → 草稿上画布 → 人调位置字号 → 示例数据预览 → 打样 → 保存 |
| 期望 | 常用物料标签压到一次会话 + 少量微调即可打样 |

### 5.2 路径 B：改一张旧模板

| | 步骤 |
| --- | --- |
| 手工 | 打开 → 凭记忆改 → 另存一份。换尺寸、加字段、换仓别时容易漏绑、错位 |
| 助手 | 先问「有哪些字段、有什么风险」→ 说要改的内容 → 大改先确认 → 不对就整笔撤销或打开某版 |
| 边界 | 看不懂的旧脚本只读说明，不删除不覆盖。复杂稿仍以人在设计器里改为准 |

### 5.3 路径 C：不用 AI

| | 步骤 |
| --- | --- |
| 手工 | 和现在用 STI 一样：打开、拖拽、保存、打印 |
| 工位（关助手） | 同一窗口完成文件、字段字典、页规格、本机打印。对话栏只提示不可用，不挡主操作 |
| 仍有价值 | 即使完全不用助手，字段字典和本机打样仍比「STI + 记事本」少一层对不齐 |

## 6. 谁受益最大

| 角色 | 手工时的痛 | 用上助手之后 |
| --- | --- | --- |
| 模板设计人员（主用户） | 出稿慢、改规格重复、字段绑错、要自己记条码规则 | 骨架和绑定交给助手；自己把时间花在对样张和难排的版式 |
| 业务提出人 | 不会 STI，用文字/截图来回说明，轮次多 | 口语描述即可看到草稿；确认导出的 PDF/PNG，不必进设计器 |
| 管理员 | 能力绑在少数人身上，交接成本高 | 字段字典、页预设、工具规则是程序资产；模型可关、密钥不进安装包 |

现场打印人员是二期用户，第一期不按「选模板套打」承诺助手收益。

---

## 7. 这些好处不成立的地方

整理「相对手工的好处」时，必须同时写清边界。否则会把助手理解成自动出稿、无人复核。

标签出错是实物损失。助手加速从需求到草稿、从旧稿到改稿。样张必须人确认。产品明确不做自动下发产线，也不承诺「模型保证扫码通过」。

| 仍要人做 / 第一期不做 | 原因 | 手工是否本来就要做 |
| --- | --- | --- |
| 确认样张、决定是否保存正式稿 | 打得出、绑得对高于生成得好看；人是最终编辑者 | 要 |
| 真机扫码、碳带、静区、打印机公差 | 体检只校验内容格式和版面风险，不能代替扫码枪 | 要 |
| 复杂旧稿里的脚本、助手看不懂的部分 | 只读说明「请在设计器里改」，不得删除或覆盖 | 要，而且只能人改 |
| 精细视觉：毫米级对齐、品牌感 | 中间仍是 STI 画布；助手排版是机械对齐，不是美术指导 | 要 |
| 批量仓别 / 语种变体 | 第一期明确不做；口述「做出东仓西仓两套」会说明做不到 | 现在也是复制再手改 |
| 从 ERP/WMS 拉实时数据 | 第一期只用本地 JSON 示例数据 | 现在也是离线样例或另套系统 |
